# ReTrace benchmarks

```bash
python -m benchmarks.run                                      # run and print
python -m benchmarks.run --baseline benchmarks/baseline.json  # gate: non-zero on regression
python -m benchmarks.run --write-baseline                     # re-record (a deliberate act)
```

## What this measures — and what it does not

**Measured:** the deterministic analysis path, `static_analysis.analyze()` and everything under it
— PE/ELF mitigation audit, third-party component fingerprinting, weak-crypto detection, the
packing heuristic, and parser robustness on malformed input. No LLM, no MCP server, no network.

**Not measured, and not implied by any number here:**

- decompilation, call-graph reachability, source→sink and exploitability — these need a real
  compiled program and a live Ghidra, so no figure for them exists yet;
- anything LLM-orchestrated: token counts, cost and per-model latency are structurally zero in
  this report because nothing on this path calls a model. The fields are in the schema so that
  path can be added without changing the format;
- real-world precision. The corpus is 13 synthetic fixtures. A score of 1.000 on it means "on
  these known inputs the analyzers report exactly the right things", **not** "ReTrace is precise".
  Treat it as a regression gate, not as evidence of product quality.

## Why the fixtures are synthetic

Generated by `benchmarks/synth.py`, which builds genuinely parseable PE32+ and ELF64 images:

- **no toolchain** — a corpus needing gcc or MSVC runs on one machine and nowhere else;
- **no committed binaries** — opaque blobs are unreviewable, and the release artifact must
  provably contain no samples;
- **exact ground truth** — mitigations, imports, version banners and crypto markers are *chosen*,
  so "find X here and nothing else" is a statement about a known input;
- **byte-identical across runs** — no timestamps, no randomness, so cross-release comparison means
  something.

Nothing here is a real program; there is no executable code in any fixture and nothing is run.

## How scoring works

`expected` is **exhaustive** per fixture. Anything reported and not expected is a false positive.
A harness that only asks "were the planted defects found" measures recall and calls it quality —
but the cost of a vulnerability-research tool is the noise it produces, so the corpus declares the
complete correct answer.

Ground truth is written from what each fixture **is**, never from what ReTrace currently reports.
A corpus of snapshots measures "nothing changed"; a corpus derived from the input measures whether
the tool is right.

Findings are identified by `vuln_type` plus the discriminating tail of the title
(`hardening/dep-nx`, `weak-crypto/rc4`). CWE alone is too coarse — six different missing
mitigations all map to CWE-693 — and the full title is too brittle.

## The corpus

| Fixture | Exercises |
|---|---|
| `pe_hardened_benign.exe` | all mitigations set, benign strings — the silence case |
| `pe_unhardened.exe` | every DllCharacteristics bit clear, relocations stripped |
| `pe_vulnerable_components.exe` | EOL OpenSSL banner + MD5/RC4 **API symbols** |
| `pe_patched_components.exe` | the patched half of the pair: current OpenSSL, modern primitives |
| `pe_crypto_word_in_prose.exe` | anti-FP: "MD5" and "SHA-1" in user-facing prose, no crypto API |
| `pe_compressed_resources.exe` | anti-FP: high-entropy `.rsrc` + normal imports is an installer |
| `pe_packed.exe` | two corroborating signals: high-entropy code *and* a 2-import table |
| `elf_hardened` / `elf_unhardened` | PIE, NX via GNU_STACK, RELRO |
| `malformed_truncated_pe.exe` | MZ header, nothing coherent after it |
| `malformed_header_only.bin` | magic number followed by noise |
| `negative_plain_text.txt` | a non-binary file must produce nothing |
| `negative_empty.bin` | zero bytes |

## What the first run found

The harness earned its place on the first run: `malformed_header_only.bin` — 514 bytes of `MZ`
plus a byte ramp — was reported as **MEDIUM "Likely packed / obfuscated"**. Entropy 8.0 over a
uniform byte ramp tripped the whole-image check, and `pefile` having failed to parse meant the
import-count corroboration defaulted to "tiny". A packing claim is a claim about a *program*, and
there was no program there.

Fixed in `reforge/static_analysis.py` by requiring that the image actually parsed and is at least
one page long before packing can be assessed.

| | before | after |
|---|---|---|
| precision | 0.975 | **1.000** |
| recall | 1.000 | 1.000 |
| F1 | 0.987 | **1.000** |
| false positives | 1 | **0** |
| FP per artifact | 0.077 | **0.000** |

## The source→sink dimension

Candidate chains are not findings — they are where to look — so counting them as false positives
would be wrong. But their *volume* is the cost the analyst pays, so it is measured in its own
right: rows emitted, maximum confidence, and whether anything claimed a tier its evidence does not
support. Each fixture declares a ceiling (`ChainExpectation`).

What this does **not** measure: whether a real chain is found. That needs a compiled program with
a planted vulnerability and a live Ghidra, which this corpus deliberately avoids. Recall on real
source→sink chains is unmeasured, and no number here implies otherwise.

## Adding a fixture

1. Add it to `benchmarks/corpus.py` with an `expected` set derived from the specification and a
   `rationale` explaining *why* that is the right answer — `test_every_fixture_states_why…`
   enforces that the rationale exists.
2. Run `python -m benchmarks.run`. If the tool disagrees with the ground truth, decide which one
   is wrong. Changing the expectation to match the output is only correct when the expectation was
   wrong.
3. Re-record with `--write-baseline` and put the before/after numbers in the changelog.

The suite fails if the corpus and the baseline drift apart, so a fixture cannot be added and left
unmeasured.
